The `outerproduct.model` module contains the objects you work with after training. A plain `Model` handles predictions; a `ReasoningModel` extends it with feature-level explanations, counterfactual scenarios, and global driver analysis. Both are produced asynchronously: you call `.wait()` on a job handle and receive the model object once training completes.

You score a model on a `DataFrame`: a query derived from the tables in your workspace, built with `ws.table(name)` or `ws.sql(...)`. The same `DataFrame` queries feed `predict`, `explain`, `predict_and_explain`, and `scenario`.

## Model

`Model` is produced by `Trainer.configure().run().wait()`. Use it when you need predictions but do not require explanations.

### `model.predict()`

```python
model.predict(df: DataFrame) -> numpy.ndarray
```

Scores every row in `df` and returns a one-dimensional NumPy array of predictions. The SDK validates the `DataFrame`'s column schema against the model's training-time schema before the request leaves your machine, so mismatched or missing features raise a descriptive local error rather than a server-side 400.

<ParamField body="df" type="DataFrame" required>
  A `DataFrame` built from a registered table, for example `ws.table("customers")` or `ws.sql("SELECT ... FROM customers")`. Column names must match the features seen during training.
</ParamField>

<ResponseField name="returns" type="numpy.ndarray">
  A 1-D array of shape `(n_samples,)` containing the model's prediction for each row. For binary classification, values are class-1 probabilities. For regression, values are the predicted target.
</ResponseField>

```python
import outerproduct as op

op.init(api_key="your-api-key")
ws = op.Workspace()

score = ws.table("customers").filter(op.col("signup_year") == 2025)
predictions = model.predict(score)  # numpy.ndarray, shape (n_samples,)

print(predictions[:5])
# [0.82, 0.14, 0.67, 0.91, 0.33]
```

## ReasoningModel

`ReasoningModel` is produced by `op.reasoning.fit().wait()`. It is a superset of `Model` (all `predict()` behaviour is identical) and adds explanation, counterfactual, and global-driver methods.

<Note>
  You need a `ReasoningModel` any time you want feature attributions or counterfactuals. Train one with `op.reasoning.fit()` instead of `Trainer`.
</Note>

### `model.predict()`

Identical to [`Model.predict()`](#modelpredict) above: accepts a `DataFrame` and returns a `numpy.ndarray` of shape `(n_samples,)`.

```python
import outerproduct as op

op.init(api_key="your-api-key")
ws = op.Workspace()

ws.register_csv("customers.csv", table_name="customers")
train = ws.table("customers")

model = op.reasoning.fit(
    train, task=op.Binclass(label_column="churn")
).wait()

score = ws.table("customers").filter(op.col("signup_year") == 2025)
predictions = model.predict(score)
```

### `model.explain()`

```python
model.explain(df: DataFrame) -> Reasoning
```

Returns per-sample feature attributions for every row in `df`. Each attribution value reflects how much that feature pushed the prediction up or down relative to the model's baseline.

<ParamField body="df" type="DataFrame" required>
  Inference rows as a `DataFrame`, for example `ws.table("customers")`. Column schema must match the training data.
</ParamField>

<ResponseField name="returns" type="Reasoning">
  A `Reasoning` object with three attributes.

  <Expandable title="Reasoning attributes">
    <ResponseField name="feature_names" type="list[str]">
      Ordered list of feature names corresponding to the columns in `attributions`.
    </ResponseField>

    <ResponseField name="attributions" type="numpy.ndarray">
      Array of shape `(n_samples, n_features)`. Each row gives the per-feature attribution for the corresponding input row. Positive values indicate the feature pushed the prediction toward the positive class; negative values push it away.
    </ResponseField>

    <ResponseField name="rules" type="list[str] | None">
      Human-readable decision rules summarising the model's logic for the queried rows, or `None` if the model type does not support rule extraction.
    </ResponseField>
  </Expandable>
</ResponseField>

```python
score = ws.table("customers").filter(op.col("signup_year") == 2025)
reasoning = model.explain(score)

print(reasoning.feature_names)
# ["age", "income", "credit_score"]

print(reasoning.attributions.shape)
# (100, 3)

if reasoning.rules:
    for rule in reasoning.rules:
        print(rule)
# "IF credit_score < 650 AND income < 40000 THEN churn (confidence 0.87)"
```

### `model.predict_and_explain()`

```python
model.predict_and_explain(df: DataFrame) -> tuple[numpy.ndarray, Reasoning]
```

Returns predictions and local explanations in a single API round-trip. Prefer this over calling `predict()` and `explain()` separately when you need both.

<ParamField body="df" type="DataFrame" required>
  Inference rows as a `DataFrame`.
</ParamField>

<ResponseField name="returns" type="tuple[numpy.ndarray, Reasoning]">
  A two-element tuple. The first element is the predictions array (shape `(n_samples,)`). The second is a `Reasoning` object identical in structure to the one returned by `explain()`.
</ResponseField>

```python
score = ws.table("customers").filter(op.col("signup_year") == 2025)
predictions, reasoning = model.predict_and_explain(score)

for i, (pred, attrs) in enumerate(zip(predictions, reasoning.attributions)):
    top_feature = reasoning.feature_names[attrs.argmax()]
    print(f"Row {i}: score={pred:.2f}, top driver={top_feature}")
```

### `model.get_global_drivers()`

```python
model.get_global_drivers() -> Reasoning
```

Returns a model-wide `Reasoning` summarising which features are most important across the entire training distribution, rather than for a specific set of input rows.

<ResponseField name="returns" type="Reasoning">
  A `Reasoning` object where `attributions` has shape `(n_features,)`, one scalar importance value per feature. `feature_names` is aligned with `attributions`. `rules` is `None` for global results.
</ResponseField>

```python
reasoning = model.get_global_drivers()

for name, importance in zip(reasoning.feature_names, reasoning.attributions):
    print(f"{name}: {importance:.4f}")

# credit_score: 0.3821
# income:       0.2945
# age:          0.1703
```

<Tip>
  Use `get_global_drivers()` as a quick sanity check after training: if a feature you expected to matter is near zero, verify the column was present in the training data.
</Tip>

### `model.scenario()`

```python
model.scenario(
    df: DataFrame,
    *,
    target_class: int | str | None = None,
    n_trials: int = 500,
    max_steps: int = 30,
) -> ScenarioResult
```

Runs a counterfactual search for each row in `df`, finding the minimal feature edits that would shift the prediction to `target_class`. Each row is treated independently; results are returned together in a `ScenarioResult`.

<ParamField body="df" type="DataFrame" required>
  Query rows to analyse, as a `DataFrame`. Each row receives its own set of counterfactual candidates.
</ParamField>

<ParamField body="target_class" type="int | str | None">
  The class you want each counterfactual to reach (for binary classification, the class to flip rows into). Defaults to `None`.
</ParamField>

<ParamField body="n_trials" default="500" type="int">
  Number of independent search attempts per query row. More trials improve the chance of finding a shorter path but increase latency. Defaults to `500`.
</ParamField>

<ParamField body="max_steps" default="30" type="int">
  Maximum number of feature edits allowed per attempt. Constraining this produces more actionable (smaller) counterfactuals. Defaults to `30`.
</ParamField>

<ResponseField name="returns" type="ScenarioResult">
  A `ScenarioResult` containing one `QueryResult` per input row. See [ScenarioResult](#scenarioresult) below for the full object tree.
</ResponseField>

<CodeGroup>

```python Basic scenario
import outerproduct as op

op.init(api_key="your-api-key")
ws = op.Workspace()

queries = ws.register_pylist(
    [
        {"age": 25, "income": 50000, "credit_score": 620},
        {"age": 40, "income": 85000, "credit_score": 710},
    ],
    table_name="queries",
)

result = model.scenario(queries, target_class=1)

for q in result.queries:
    print(f"Query {q.query_index}: baseline={q.baseline_prediction:.2f}")
    if q.already_at_desired_class:
        print("  Already at target class, no change needed.")
        continue
    for cf in q.counterfactuals:
        print(f"  Candidate ({cf.n_changes} changes):")
        for feature, change in cf.changes.items():
            print(f"    {feature}: {change.before} → {change.after}")
```

```python Tuned search
result = model.scenario(
    queries,
    target_class=1,
    n_trials=200,   # more attempts per row
    max_steps=3,    # cap edits to keep changes actionable
)
```

</CodeGroup>

## ScenarioResult

`ScenarioResult` is returned by `model.scenario()`. It groups all counterfactual results for a batch of query rows.

<ResponseField name="queries" type="list[QueryResult]">
  One `QueryResult` per row in the input `DataFrame`, in the same order as the input rows.
</ResponseField>

---

## QueryResult

A single row's counterfactual analysis.

<ResponseField name="query_index" type="int">
  Zero-based index of this row within the input `DataFrame`, matching the original row order.
</ResponseField>

<ResponseField name="baseline_prediction" type="float">
  The model's prediction for this row before any edits are applied.
</ResponseField>

<ResponseField name="already_at_desired_class" type="bool">
  `True` if the baseline prediction already belongs to `target_class`, meaning no change is required. When `True`, `counterfactuals` will be empty.
</ResponseField>

<ResponseField name="counterfactuals" type="list[Counterfactual]">
  Candidate counterfactual edits that would shift this row's prediction to `target_class`, ordered by fewest changes first. May be empty if the search found no valid path within the configured `max_steps` and `n_trials`.
</ResponseField>

---

## Counterfactual

One candidate set of edits for a single query row.

<ResponseField name="n_changes" type="int">
  Number of features modified in this counterfactual. Smaller is generally more actionable.
</ResponseField>

<ResponseField name="changes" type="dict[str, Change]">
  Mapping from feature name to a `Change` object describing what value it held before and what it would need to become.
</ResponseField>

```python
for cf in query_result.counterfactuals:
    print(f"  {cf.n_changes} change(s):")
    for feature, change in cf.changes.items():
        print(f"    {feature}: {change.before} → {change.after}")
# 2 change(s):
#   credit_score: 620 → 680
#   income: 50000 → 62000
```

---

## Change

Describes a single feature edit within a `Counterfactual`.

<ResponseField name="before" type="any">
  The feature's value in the original query row.
</ResponseField>

<ResponseField name="after" type="any">
  The value the feature would need to take for the counterfactual to reach `target_class`.
</ResponseField>
