## `Model`

A trained, deployable predictor.

Returned by `run`. `Model` is intentionally
minimal — it exposes prediction and persistence, nothing else. For
explanations, counterfactuals, and segmentation, configure the trainer
with `reasoning=True` to get a `ReasoningModel` instead.

Models are usually constructed by the trainer; users rarely call the
constructor directly.

label before scoring.
</ResponseField>

<ResponseField name="feature_names" type="list[str] | None">
  The trained feature columns, in order.

When not threaded in from `fit`/`run` (e.g. a handle from
`get_model`), this is recovered from the schema
manifest — the same sidecar `schema` reads — so it no longer
comes back `None` for a server-backed model. Cached on the
instance.
</ResponseField>

<ResponseField name="schema" type="list[FieldDef]">
  Per-column schema of the training data this model was fit on.

Returned from local `feature_names` when available; otherwise
lazy-fetched from `GET /v1/models/{id}/schema` (the manifest
sidecar written at fit time). Result is cached on the instance.

The storage dtype isn't recoverable client-side here, so each column's
`datatype` defaults to `Real` — `schema` is a names/shape
convenience, not the authoritative server schema.
</ResponseField>

## `DiffModel`

A trained `Model` with native gradient access.

Server-side handle to a trainer `DiffModel` subclass — currently
`TabM`, `XRFM`, or `DiffEnsemble`. The class mirrors the trainer
inheritance hierarchy (`DiffModel` is a `Model`) so anywhere a
`Model` is accepted, a
`DiffModel` works too.
