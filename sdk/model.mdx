## `Model`

A trained, deployable predictor.

Returned by [`Trainer.run`](/sdk/trainer#trainer-run). `Model` is
intentionally minimal — it exposes prediction and persistence, nothing else.
For explanations, scenarios, and segmentation, use
[`fit`](/sdk/reasoning#op-reasoning-fit) to get a
[`ReasoningModel`](/sdk/model#reasoningmodel) instead.

Models are usually constructed by the trainer; users rarely call the
constructor directly.

<ResponseField name="id" type="str">
  The model's unique identifier.
</ResponseField>

<ResponseField name="label_column" type="str | None">
  Name of the target column from the training dataset, or `None`
if unknown.
</ResponseField>

<ResponseField name="feature_names" type="list[str] | None">
  The trained feature columns, in order.

Falls back to the model's `schema`
when the names aren't known locally (e.g. a handle from
[`get_model`](/sdk/overview#op-get_model)).
</ResponseField>

<ResponseField name="schema" type="list[FieldDef]">
  Per-column schema of the training data this model was fit on.

Returned from local `feature_names` when available; otherwise
lazy-fetched from `GET /v1/models/{id}/schema` and cached.

Each column's `datatype` defaults to `Real` — `schema` is a
names/shape convenience, not the authoritative server schema.
</ResponseField>

## `ReasoningModel`

A [`Model`](/sdk/model#model) augmented with explanation and reasoning methods.

Returned by [`fit`](/sdk/reasoning#op-reasoning-fit). Inherits everything from
[`Model`](/sdk/model#model) and adds methods for local/global
explanations and scenarios.

The return types of these methods are
[`Reasoning`](/sdk/reasoning#reasoning) (single explanation) and
[`ScenarioResult`](/sdk/reasoning#scenarioresult) (scenario
search results).

### `ReasoningModel.scenario()`

```python
scenario(df: DataFrame, *, target_class: int | str | None = None, n_trials: int = 500, max_steps: int = 30, decision_threshold: float = 0.5, random_state: int | None = 42, constraints: dict[str, Any] | None = None) -> ScenarioResult
```

Search for scenarios: minimal feature changes that flip the prediction.

**Parameters**

<ParamField body="df" type="DataFrame" required>
  Starting point(s) for the search. Each row is one query.
</ParamField>

<ParamField body="target_class" type="int | str | None">
  Desired class index. If omitted, defaults to `1`. A
numeric string is accepted (coerced via `int`); non-numeric
class labels are not supported.
</ParamField>

<ParamField body="n_trials" type="int">
  Number of scenario attempts per query.
</ParamField>

<ParamField body="max_steps" type="int">
  Maximum number of edit steps per attempt.
</ParamField>

<ParamField body="decision_threshold" type="float">
  Probability cutoff for the positive class. Set
away from `0.5` to target a different operating point.
</ParamField>

<ParamField body="random_state" type="int | None">
  Random seed for reproducibility. `None` disables
seeding.
</ParamField>

<ParamField body="constraints" type="dict[str, Any] | None">
  Per-feature constraints applied during the search. Keys
are feature names; values are dicts (or
`FeatureConstraintSchema`
instances) with optional keys `immutable` (bool), `monotonic`
(`"increase"` or `"decrease"`), `value_range` (`[lo, hi]`), and
`allowed_values` (list).
</ParamField>

**Returns**

<ResponseField name="returns" type="ScenarioResult">
  A [`ScenarioResult`](/sdk/reasoning#scenarioresult) with one [`QueryResult`](/sdk/reasoning#queryresult) per input row, each carrying the original query, its baseline prediction, and the list of `Scenario` candidates found.
</ResponseField>
