## `Trainer`

Configures and runs training to produce a `Model`.

The full lifecycle is:

1. `configure` — describe what to train, where, and how.
2. `run` — submit the configured plan and return a
   `TrainingJob` handle. Call
   `wait` to block for the trained
   `Model`.

`Trainer` resolves to a plain `Model`. To
produce a `ReasoningModel` (with explain,
get_global_drivers, scenario, segment methods) use
`fit` instead.

### `Trainer.configure()`

```python
configure(df: DataFrame, *, task: Task | None = None, hpo_space: HPOSpace | None = None, metric: Metric | list[Metric] | None = None) -> Trainer
```

Configure a trainer for `df` and return it ready to `run`.

Parameters
----------
df : `DataFrame`
    Training data — `op.table(name)` over a registered source,
    optionally filtered/selected.
task : `Task`, optional
    The learning task and its target columns — one of
    `Regression`, `Binclass`, `Multiclass`, `Forecasting`,
    `SequenceRegression`, `SequenceBinclass`, or
    `SequenceMulticlass` (each carries `label_column`; the
    time-series / sequence variants also carry `id_column` /
    `timestamp_column`). Required for supervised training.
hpo_space : `HPOSpace`, optional
    The search space — candidate model families and, per family, which
    hyperparameters are fixed vs searched. Must be a built
    `HPOSpace`: construct it with
    `from_dict` or `HPOSpace().add(...)` — a raw dict is
    rejected. Defaults to a curated space chosen from the dataset's size
    and schema.
metric : `Metric` or list of `Metric`, optional
    One metric to optimise directly, or a list to optimise jointly
    via Optuna's native multi-objective (Pareto) search, with no
    metric privileged.

Returns
-------
`Trainer`
    A configured trainer. Call `run` to start training.

### `Trainer.run()`

```python
run(optimizer: Optimizer | None = None, *, n_cv_splits: int | None = None, ensemble: bool = False, random_state: int = 42) -> TrainingJob
```

Submit the configured training plan and return a job handle.

Parameters
----------
optimizer : `Optimizer`, optional
    How to search the space — the sampler (`"tpe"` / `"random"` /
    `"cmaes"`) and a round-structured trial budget
    (`n_trials_per_step` proposed per round × `n_steps` rounds).
    If omitted, the server uses a default optimizer.
n_cv_splits : int, optional
    Number of cross-validation splits. If omitted, the server
    chooses a default.
ensemble : bool, default False
    Whether to ensemble the top-performing trials.
random_state : int, default 42
    Random seed for reproducibility.

Returns
-------
`TrainingJob`
    Handle to the running job. Call
    `wait` to block until
    training finishes and return the trained
    `Model`, or use
    `status` to poll. To get a
    `ReasoningModel` instead, use
    `fit`.

## `Metric`

An evaluation metric used to score candidate models.

Parameters
----------
name : str
    Display name used in logs and reports. Forwarded to the server.
fn : callable, optional
    Scoring callable with signature `fn(y_true, y_pred) -> float`.
    Higher values are better. **Not yet supported** — setting `fn`
    raises in this version because callables can't be serialised over
    the wire. The metric is resolved server-side by `name`.
