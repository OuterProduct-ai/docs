`outerproduct.Trainer` is the low-level training interface that gives you full control over the model selection and hyperparameter search that runs on the OuterProduct platform. You describe **what** to search with an `HPOSpace` (candidate model families and, per family, which hyperparameters are fixed versus searched), and **how** to search it with an `Optimizer` (a sampler plus a trial budget). Both are resolved server-side. The result is a single trained `Model` representing the best configuration found. If you also need feature-level explanations, use `op.reasoning.fit()` instead, which runs the same search and returns a `ReasoningModel`.

You train on a `DataFrame`: a query derived from the tables in your workspace, built with `ws.table(name)` or `ws.sql(...)`.

---

## `Trainer.configure()`

Class method that creates a configured `Trainer` ready to launch a training job.

```python
op.Trainer.configure(
    df,
    *,
    task=None,
    hpo_space=None,
    metric=None,
)
```

### Parameters

<ParamField body="df" type="DataFrame" required>
  The training data as a `DataFrame`. Build one from a registered table with `ws.table("customers")` or `ws.sql("SELECT ... FROM customers")`, optionally chaining `filter`, `select`, `join`, and other relational ops.
</ParamField>

<ParamField body="task" type="Task | None">
  The supervised learning task, which carries the target `label_column` (and, for time-series and sequence variants, the `id_column` / `timestamp_column`). Pass the config that matches your problem:

  | Config | Use when |
  | --- | --- |
  | `op.Binclass(label_column=...)` | Binary classification (exactly two classes) |
  | `op.Multiclass(label_column=...)` | Multi-class classification (three or more classes) |
  | `op.Regression(label_column=...)` | Continuous numerical target |
  | `op.Forecasting(label_column=..., id_column=..., timestamp_column=..., horizon=..., lookback=...)` | Time-series forecasting (accepted, not yet executable) |
  | `op.SequenceBinclass(label_column=..., id_column=..., timestamp_column=...)` | One binary label per entity over the entity's sequence |
  | `op.SequenceMulticlass(label_column=..., id_column=..., timestamp_column=...)` | One multi-class label per entity over the entity's sequence |
  | `op.SequenceRegression(label_column=..., id_column=..., timestamp_column=...)` | One continuous label per entity (accepted, not yet executable) |

  Required for supervised training.
</ParamField>

<ParamField body="hpo_space" type="HPOSpace | None">
  The search space: which model families to consider and, per family, which hyperparameters are fixed versus searched. Must be a built `op.HPOSpace`, constructed with `op.HPOSpace.from_dict(...)` or `op.HPOSpace().add(...)`. A raw `dict` is rejected with a `TypeError`. If omitted, OuterProduct picks a curated space based on your dataset's size and schema. See [The `HPOSpace` class](#the-hpospace-class) below.
</ParamField>

<ParamField body="metric" type="Metric | list[Metric] | None">
  One or more evaluation metrics, each wrapped in `op.Metric`. Pass a single metric to optimize it directly. Pass a list to optimize all of them jointly: OuterProduct uses Optuna's native multi-objective optimization to explore the Pareto frontier of trade-offs between the listed metrics, so you do not have to pick a fixed weighting up front. If omitted, a default metric is chosen based on the task type.

  <Expandable title="Common metric names">
    | Name | Task |
    | --- | --- |
    | `"auc"` | Binary classification |
    | `"accuracy"` | Classification |
    | `"logloss"` | Classification |
    | `"f1"` | Classification |
    | `"rmse"` | Regression |
    | `"mae"` | Regression |
  </Expandable>
</ParamField>

### Returns

<ResponseField name="return value" type="Trainer">
  A configured `Trainer` instance. Call `.run()` on it to submit the training job.
</ResponseField>

### Example

```python
import outerproduct as op

op.init()
ws = op.Workspace()

ws.register_csv("customers.csv", table_name="customers")
train = ws.table("customers")

trainer = op.Trainer.configure(
    train,
    task=op.Binclass(label_column="churn"),
    hpo_space=op.HPOSpace.from_dict(
        {"models": [{"family": "tabm"}, {"family": "xgboost"}]}
    ),
    metric=op.Metric("auc"),
)
```

## `trainer.run()`

Submit the configured training job to the OuterProduct platform. Returns immediately with a `Job` handle; training runs asynchronously server-side.

```python
trainer.run(
    optimizer=None,
    *,
    n_cv_splits=None,
    ensemble=False,
    random_state=42,
)
```

### Parameters

<ParamField body="optimizer" type="Optimizer | None">
  How to search the space: the sampler and a round-structured trial budget. Build one with `op.Optimizer(kind=..., n_trials_per_step=..., n_steps=...)`. If omitted, the server uses a default optimizer. See [The `Optimizer` class](#the-optimizer-class) below.
</ParamField>

<ParamField body="n_cv_splits" type="int | None">
  Number of cross-validation splits used to score each trial. If omitted, the server chooses a default based on dataset size.
</ParamField>

<ParamField body="ensemble" type="bool" default="False">
  Whether to ensemble the top-performing trials into the returned model instead of returning the single best configuration. Single-objective only.
</ParamField>

<ParamField body="random_state" type="int" default="42">
  Random seed for reproducible search and splits.
</ParamField>

### Returns

<ResponseField name="return value" type="Job[Model]">
  A non-blocking job handle. The job runs server-side; use the handle to poll status, block for the result, or retrieve the raw response payload.
</ResponseField>

## The `HPOSpace` class

An `HPOSpace` describes **what to search**. It holds one `ModelParamSpace` per candidate model family. Each `ModelParamSpace` names which hyperparameters are **searched** (a `Float`, `Int`, `Categorical`, or `Mixture` distribution) and which are **fixed** (a constant merged into every fit). All families in the space are tuned in the same search; the platform returns the single best configuration across all of them (or an ensemble, if `ensemble=True`).

If you pass no `hpo_space`, the platform defaults to a curated space chosen from your dataset's size and schema. The default tabular families are `tabm` and `xrfm`.

<Note>
  `Trainer.configure()` requires a built `HPOSpace`, not a raw `dict`. Construct it with `op.HPOSpace.from_dict(...)` or `op.HPOSpace().add(...)`; passing a plain `dict` raises a `TypeError`.
</Note>

### Available model families

| Family | Identifier |
| --- | --- |
| TabM (default) | `"tabm"` |
| xRFM (default) | `"xrfm"` |
| XGBoost | `"xgboost"` |
| TabICL | `"tabicl"` |

Listing a family with no hyperparameters (for example `{"family": "tabm"}`) searches that family's curated default space. Naming individual hyperparameters narrows or overrides that default for the ones you name.

### Building a space

<CodeGroup>

```python from_dict
import outerproduct as op

# Two families. "tabm" searches its curated default space; "xgboost"
# overrides two dimensions and pins one constant.
space = op.HPOSpace.from_dict(
    {
        "models": [
            {"family": "tabm"},
            {
                "family": "xgboost",
                "params": {
                    # Distributions (dicts carrying "kind") are searched.
                    "eta": {"kind": "float", "low": 1e-4, "high": 0.3, "log": True},
                    "max_depth": {"kind": "int", "low": 3, "high": 10},
                    # Bare values are fixed constants.
                    "n_estimators": 1000,
                },
            },
        ]
    }
)
```

```python fluent builder
import outerproduct as op

# The same space, built with the fluent ModelParamSpace API.
tabm = op.ModelParamSpace(family="tabm")

xgb = (
    op.ModelParamSpace(family="xgboost")
    .float("eta", 1e-4, 0.3, log=True)   # searched: log-uniform float
    .int("max_depth", 3, 10)             # searched: integer range
    .const("n_estimators", 1000)         # fixed constant
)

space = op.HPOSpace().add(tabm).add(xgb)
```

</CodeGroup>

### `HPOSpace` reference

<ResponseField name="HPOSpace.from_dict(raw)" type="HPOSpace">
  Compile a plain `dict` (shape `{"models": [...]}`) into a typed `HPOSpace`. Passing an existing `HPOSpace` returns it unchanged.
</ResponseField>

<ResponseField name="HPOSpace().add(model)" type="HPOSpace">
  Append a `ModelParamSpace` and return the space, so calls chain.
</ResponseField>

<ResponseField name="space.families()" type="list[str]">
  The family identifiers currently in the space, in order.
</ResponseField>

### `ModelParamSpace`

One model family's search. Construct it as `op.ModelParamSpace(family="tabm")`, then chain builder methods. Each builder returns the same `ModelParamSpace` so calls compose.

<ResponseField name=".float(name, low, high, log=False)" type="ModelParamSpace">
  Search a continuous float dimension, optionally log-scaled.
</ResponseField>

<ResponseField name=".int(name, low, high, log=False)" type="ModelParamSpace">
  Search an integer dimension, optionally log-scaled.
</ResponseField>

<ResponseField name=".categorical(name, choices)" type="ModelParamSpace">
  Search uniformly over an explicit list of values.
</ResponseField>

<ResponseField name=".mixture(name, inner, spike=0.0)" type="ModelParamSpace">
  Search a spike-and-slab dimension: take the `spike` value (default `0.0`) with some probability, otherwise draw from the `inner` distribution. Use this for hyperparameters such as dropout or weight decay that are often best left off. `inner` is a `Float`, `Int`, or `Categorical` instance, for example `op.Float(low=0.0, high=0.5)`.
</ResponseField>

<ResponseField name=".const(name, value)" type="ModelParamSpace">
  Pin a hyperparameter to a fixed constant, merged into every fit.
</ResponseField>

### Distribution types

When building a dict-shaped space, searched dimensions are dicts carrying a `kind`. You can also construct them directly as `op.Float`, `op.Int`, `op.Categorical`, and `op.Mixture` (handy for the `inner` of a `Mixture`).

| Type | Fields | Searches |
| --- | --- | --- |
| `op.Float` | `low`, `high`, `log=False` | A continuous float, optionally log-scaled |
| `op.Int` | `low`, `high`, `log=False` | An integer range, optionally log-scaled |
| `op.Categorical` | `choices` | A uniform choice over an explicit list |
| `op.Mixture` | `spike=0.0`, `inner` | A spike value, else a draw from `inner` |

```python
import outerproduct as op

space = op.HPOSpace().add(
    op.ModelParamSpace(family="tabm")
    .float("lr", 1e-4, 3e-3, log=True)
    .categorical("n_blocks", [1, 2, 3, 4])
    # weight_decay is 0.0 unless the gate fires, then a log-uniform draw.
    .mixture("weight_decay", op.Float(low=1e-4, high=1e-1, log=True))
)
```

## The `Optimizer` class

An `Optimizer` describes **how to search**: a sampler plus a round-structured trial budget.

```python
op.Optimizer(kind="tpe", n_trials_per_step=2, n_steps=2)
```

Each optimization round proposes `n_trials_per_step` trials, evaluates them, folds the results back, then proposes the next round; `n_steps` rounds run in sequence. The total number of trials searched is `n_trials_per_step * n_steps` (also returned by `optimizer.total_trials()`).

<ParamField body="kind" type="string" default="tpe">
  The sampler algorithm:

  - `"tpe"` _(default)_: Bayesian, Tree-structured Parzen Estimator. Learns from earlier rounds, so a higher `n_steps` pays off.
  - `"random"`: random search. Ignores prior observations, so sequential rounds buy nothing: `n_steps` is collapsed to `1` and all trials run in a single round.
  - `"cmaes"`: CMA-ES, an evolutionary strategy well suited to continuous spaces.
</ParamField>

<ParamField body="n_trials_per_step" type="int" default="2">
  Trials proposed and evaluated per optimization round. Must be at least `1`.
</ParamField>

<ParamField body="n_steps" type="int" default="2">
  Number of sequential optimization rounds. Must be at least `1`. For `kind="random"`, this is forced to `1`.
</ParamField>

```python
import outerproduct as op

# Bayesian search: 5 rounds of 4 trials each = 20 trials total.
optimizer = op.Optimizer(kind="tpe", n_trials_per_step=4, n_steps=5)
print(optimizer.total_trials())  # 20

# Random search: 50 trials in a single round.
quick = op.Optimizer(kind="random", n_trials_per_step=50)
```

<Tip>
  Start with `kind="random"` for a fast baseline. Switch to `kind="tpe"` (or `"cmaes"`) with more `n_steps` when you want the search to learn from earlier rounds and refine toward the best region.
</Tip>

## The `Metric` class

Wrap a metric name in `op.Metric` to pass it to `Trainer.configure()`.

```python
op.Metric(name, fn=None)
```

<ParamField body="name" type="string" required>
  The metric identifier string, resolved server-side. Common values:

  | Name | Description |
  | --- | --- |
  | `"auc"` | Area under the ROC curve (binary classification) |
  | `"accuracy"` | Fraction of correct predictions |
  | `"logloss"` | Logarithmic loss |
  | `"f1"` | F1 score |
  | `"rmse"` | Root mean squared error (regression) |
  | `"mae"` | Mean absolute error (regression) |
</ParamField>

<ParamField body="fn" type="callable | None">
  A custom scoring callable `fn(y_true, y_pred) -> float`. **Not supported yet**: setting `fn` raises `NotImplementedError`, because callables cannot be serialized to the server. Metrics are resolved by `name` for now.
</ParamField>

```python
metric = op.Metric("auc")
```

## The `Job` Handle

`trainer.run()` (and `op.reasoning.fit()`) return a `Job` handle immediately. Training runs asynchronously; use the handle to interact with it.

### `job.status()`

Poll the current state of the job without blocking.

```python
status = job.status()
# Returns: "pending" | "running" | "completed" | "failed"
```

<ResponseField name="return value" type="str">
  One of `"pending"`, `"running"`, `"completed"`, or `"failed"`.
</ResponseField>

### `job.wait()`

Block the current thread until the job finishes, then return the trained model.

```python
model = job.wait()
```

<ResponseField name="return value" type="Model">
  The trained `Model` once the job completes successfully. Raises if the job failed.
</ResponseField>

### `job.results()`

Retrieve the raw result payload from the platform once the job has completed. Useful for inspecting job metadata, artifact URIs, or debugging.

```python
result = job.results()
```

<ResponseField name="return value" type="dict">
  A dictionary containing the raw response from the OuterProduct API, including job IDs, artifact URIs, and timing information. Only available after the job status is `"completed"`.
</ResponseField>

<Note>
  `.wait()` is the simplest path for linear scripts. Use `.status()` and `.results()` when you want to run other work while training proceeds, or when you are managing jobs across multiple datasets.
</Note>

    ```python
    import time
    import outerproduct as op

    op.init()
    ws = op.Workspace()

    ws.register_csv("loans.csv", table_name="loans")
    train = ws.table("loans")
    trainer = op.Trainer.configure(train, task=op.Binclass(label_column="approved"))

    # Submit and continue doing other work.
    job = trainer.run(optimizer=op.Optimizer(kind="tpe", n_trials_per_step=4, n_steps=5))

    while job.status() in ("pending", "running"):
        print(f"Job status: {job.status()}")
        time.sleep(10)

    if job.status() == "completed":
        model = job.wait()
        print("Training complete:", job.results())
    else:
        print("Job failed.")
    ```

## How the search works

When you call `trainer.run()`, the OuterProduct platform:

1. **Compiles the `hpo_space`** into a sampler over every family it lists, treating searched dimensions as variables and fixed constants as pinned. If you passed no space, it builds a curated default from your dataset.
2. **Runs the optimizer**: each round proposes `n_trials_per_step` configurations using the chosen sampler (`"tpe"`, `"random"`, or `"cmaes"`), scores them with `n_cv_splits`-fold cross-validation, and folds the results back before the next round. `n_steps` rounds run in sequence. With multiple metrics, this is Optuna's native multi-objective search over the Pareto frontier; no metric is privileged.
3. **Selects the result**: with a single metric, the best configuration across all families and trials (or, with `ensemble=True`, a blend of the top trials). With multiple metrics, the non-dominated trials on the Pareto frontier.
4. **Returns a `Model`**: ready for `predict()`.

Parallelism and per-trial timeouts are managed server-side. There are no SDK-level threading or timeout knobs.

<Tip>
  Leave `hpo_space` and `optimizer` unset for a quick, well-defaulted run. Reach for a custom `HPOSpace` when you want to pin or narrow specific hyperparameters, and a custom `Optimizer` when you want to control the sampler or spend a larger trial budget.
</Tip>
