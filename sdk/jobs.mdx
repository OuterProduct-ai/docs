## `Job`

Base handle for any async server operation. Keyed on `job_id`.

Not instantiated directly — use one of the subclasses returned by
[`Trainer.run`](/sdk/trainer#trainer-run) or
[`fit`](/sdk/reasoning#op-reasoning-fit).

### Properties

<ResponseField name="job_id" type="str">
  Server-assigned job identifier.
</ResponseField>

### `Job.status()`

```python
status() -> str
```

Check the current job status.

**Returns**

<ResponseField name="returns" type="str">
  One of `"pending"`, `"running"`, `"completed"`, `"failed"`.
</ResponseField>

### `Job.results()`

```python
results() -> JobResult
```

Fetch the final result payload of this job.

**Returns**

<ResponseField name="returns" type="JobResult">
  Typed wrapper over the per-job-type `result_data` envelope. Use `JobResult.model_id` for the common subject id; reach into `JobResult.raw` for everything else.
</ResponseField>

### `Job.wait()`

```python
wait(*, poll_interval: float = 2.0, poll_timeout: float = 3600.0) -> Any
```

Block until the job completes and return the result.

Subclasses override this to return a richer artifact type — e.g.
[`Model`](/sdk/model#model) for
[`TrainingJob`](/sdk/jobs#trainingjob),
[`ReasoningModel`](/sdk/model#reasoningmodel) for
[`ReasoningFitJob`](/sdk/jobs#reasoningfitjob). The base
implementation returns the typed
[`JobResult`](/sdk/jobs#jobresult), which
dataset-producing jobs read via
`JobResult.source_table_id`.

## `JobResult`

Frozen view over a completed job's `result_data` payload.

Construct via [`Job.results`](/sdk/jobs#job-results). Subject ids
(`model_id`, `source_table_id`) are written into the payload by the worker
that creates the matching row, and are exposed as typed properties here.
`raw` is the full underlying dict for fields not modeled directly.

### Properties

<ResponseField name="model_id" type="str | None">
  The model row id, when this job produced one (trainer / reasoning fit).
</ResponseField>

<ResponseField name="source_table_id" type="str | None">
  The source-table row id, when this job produced one.
</ResponseField>

## `JobFailed`

Raised by [`Job.results`](/sdk/jobs#job-results) when the server reports status='failed'.

## `JobNotReady`

Raised when [`Job.results`](/sdk/jobs#job-results) is called before the job finishes.
