### `Job.wait()`

```python
wait(*, poll_interval: float = 2.0, poll_timeout: float = 3600.0) -> Any
```

Block until the job completes and return the result.

Subclasses override this to return a richer artifact type — e.g.
`Model` for `TrainingJob`, `ReasoningModel`
for `ReasoningFitJob`. The base implementation returns the
typed `JobResult` so dataset-producing jobs can chain into
`into_dataset`.

## `TrainingJob`

Handle for a `run` call.

### `TrainingJob.into_model()`

```python
into_model() -> Model
```

Construct a `Model` from this job's completed result.

Reads the dedicated `GET /v1/training_jobs/{id}` resource — not
the generic results envelope — for the trained `model_id`.
Expects the job to have already finished — typically called from
`wait`. Raises if the resource does not carry a `model_id`
(which would indicate a server-side bug, not a client error).

If the original `run` pinned
the search to a single trainer DiffModel class (TabM / XRFM /
DiffEnsemble), returns a `DiffModel`; otherwise a plain
`Model`.

### `TrainingJob.wait()`

```python
wait(*, poll_interval: float = 2.0, poll_timeout: float = 3600.0) -> Model
```

Block until training completes, then return the trained model.

## `JobResult`

Frozen view over a completed job's `result_data` payload.

Construct via `results`. Subject ids (`model_id`,
`source_table_id`) are written into the payload by the worker that
creates the matching row, and are exposed as typed properties here.
`raw` is the full underlying dict for fields not modeled directly.

### Properties

<ResponseField name="model_id" type="str | None">
  The model row id, when this job produced one (trainer / reasoning fit).
</ResponseField>

<ResponseField name="source_table_id" type="str | None">
  The source-table row id, when this job produced one (tabularize).
</ResponseField>

## `JobFailed`

Raised by `results` when the server reports status='failed'.

## `JobNotReady`

Raised when `results` is called before the job finishes.
