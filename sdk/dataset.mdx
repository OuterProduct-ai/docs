`outerproduct.Workspace` is the single data entry point and a query session over your data. You register source tables into it (from a local file, an in-memory frame, or a cloud [connector](/sdk/connectors)), then query those tables into a `DataFrame`. A `DataFrame` is the one input that all OuterProduct training and inference functions accept: you pass it to `op.reasoning.fit()`, `model.predict()`, `model.explain()`, and `Trainer.configure()`.

The query engine embedded in the workspace is based on [Apache DataFusion](https://datafusion.apache.org/), so a `DataFrame` is a lazy relational plan. It runs server-side against your source tables when you train or score, not on your machine, and re-running it picks up current rows.

```python
import outerproduct as op

op.init()
ws = op.Workspace()
```

<Note>
  You do not pass raw files or frames to `fit` / `predict` / `explain`. You register the data in the workspace to get a source table, then query it into a `DataFrame`. The target column is not marked on the data itself; you name it later via the `task` config (e.g. `op.Binclass(label_column=...)`) when you call `op.reasoning.fit()` or `Trainer.configure()`.
</Note>

## Registering source tables

Every `register_*` method ingests data and returns the table's `DataFrame` directly. Use `register_*` with an explicit `table_name` for clarity in reference code. The `from_*` and `read_*` methods are the same but auto-name the table when `table_name` is omitted.

```python
# Local file. register_csv returns the DataFrame for the new "customers" table.
ws.register_csv("customers.csv", table_name="customers")

# In-memory pandas frame.
import pandas as pd
df = pd.DataFrame({"age": [25, 32, 47], "income": [40000, 75000, 120000]})
ws.register_pandas(df, table_name="people")
```

### From local files

`register_csv`, `register_parquet`, and `register_json` upload a local file and register it as a source table. `read_csv`, `read_parquet`, and `read_json` do the same but auto-name the table after the file when `table_name` is omitted.

```python
import outerproduct as op

op.init()
ws = op.Workspace()

ws.register_parquet("warehouse/transactions.parquet", table_name="transactions")
ws.register_csv("loans.csv", table_name="loans")

# read_* auto-names the table "loans" from the filename.
loans = ws.read_csv("loans.csv")
```

<ParamField body="path" type="str | Path" required>
  Path to the file on your local filesystem.
</ParamField>

<ParamField body="table_name" type="str">
  Name to register the table under. For `register_*`, defaults to the file stem; for `read_*`, the table is auto-named when omitted.
</ParamField>

### From in-memory frames

`register_pandas`, `register_polars`, `register_arrow`, `register_pylist`, and `register_pydict` upload an in-memory object and register it. The `from_pandas`, `from_polars`, `from_arrow`, `from_pylist`, and `from_pydict` methods do the same and auto-name the table when `table_name` is omitted.

```python
import polars as pl
import outerproduct as op

op.init()
ws = op.Workspace()

frame = pl.read_csv("loans.csv")
ws.register_polars(frame, table_name="loans")

# from_* auto-names the table.
records = ws.from_pylist([{"age": 25, "income": 40000}, {"age": 32, "income": 75000}])
```

<ParamField body="data" type="pandas.DataFrame | polars.DataFrame | pyarrow.Table | list[dict] | dict[str, list]" required>
  The in-memory object to register. The frame index is ignored; all columns become source-table columns.
</ParamField>

<ParamField body="table_name" type="str">
  Name to register the table under. Required for `register_*`; auto-named for `from_*` when omitted.
</ParamField>

### From cloud connectors

`register_s3`, `register_snowflake`, and `register_databricks` register a table that lives in a cloud source without uploading any data. Credentials are configured once in the Console and referenced by name. See the [Connectors reference](/sdk/connectors) for the full setup and signatures.

```python
import outerproduct as op

op.init()
ws = op.Workspace()

ws.register_s3("customers", "s3://my-bucket/customers.parquet", connector="prod-aws")
```

### NumPy data

There is no `register_numpy`. Build a frame from your arrays first, then register the frame:

```python
import numpy as np
import pandas as pd
import outerproduct as op

op.init()
ws = op.Workspace()

X = np.random.rand(1000, 5)
y = (X[:, 0] > 0.5).astype(int)

df = pd.DataFrame(X, columns=["f0", "f1", "f2", "f3", "f4"])
df["label"] = y
ws.register_pandas(df, table_name="synthetic")
```

## Building a DataFrame

A `DataFrame` is a query derived from your source tables. Build it in whichever style fits, then hand it to `fit`, `predict`, or `explain`. There are two ways to construct one (and `register_*` returns one directly, as above).

### `ws.table(name)`

Reference a registered table, then chain relational operations off it.

```python
df = ws.table("customers")                                   # whole table

df = (
    ws.table("customers")
    .filter(op.col("signup_year") >= 2020)
    .select("age", "income", "churn")
)
```

### `ws.sql(query)`

Write SQL against the workspace. The query can join across multiple registered source tables, including tables that came from different systems.

```python
df = ws.sql("SELECT age, income, churn FROM customers WHERE signup_year >= 2020")
```

### Expression helpers and operations

Build predicates and derived columns with `op.col("name")` and `op.lit(value)`. Comparisons accept Python literals directly, so `op.col("age") >= 18` works without wrapping `18`.

`DataFrame` supports `filter`, `select`, `with_column`, `with_columns`, `with_column_renamed`, `aggregate`, `join`, `join_on`, `sort`, `sort_by`, `limit`, `head`, `distinct`, `count`, and `materialize`. Each relational operation returns a new `DataFrame`, so you can chain them.

```python
train = (
    ws.table("customers")
    .filter(op.col("country") == "US")
    .with_column("tenure_years", op.col("signup_year") - op.lit(2015))
    .select("age", "income", "tenure_years", "churn")
)
```

## DataFrames are the core input

A `DataFrame` is the unit of work for both ML and reasoning. The same query model builds your training set and your inference set, so they are constructed the same way and stay consistent as new data lands.

```python
import outerproduct as op

op.init()
ws = op.Workspace()

ws.register_csv("loans.csv", table_name="loans")

# Training set: a query over the source table.
train = ws.table("loans")
model = op.reasoning.fit(train, task=op.Binclass(label_column="approved")).wait()

# Inference set: another query selecting the rows you want to score.
score = ws.table("loans").filter(op.col("region") == "EU")
predictions = model.predict(score)
reasoning = model.explain(score)
```

```python From NumPy
import numpy as np

```
