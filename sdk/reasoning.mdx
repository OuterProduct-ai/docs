The `outerproduct.reasoning` module is the entry point for training reasoning models and analysing their behaviour across populations. `op.reasoning.fit()` trains a `ReasoningModel` that produces both predictions and feature-level attributions. `op.reasoning.pattern_tracker.fit()` takes a fitted `ReasoningModel` and condenses its explanations over a target prediction band into a small set of named, executable filter patterns you can apply to any new data.

Both entry points take a `DataFrame` as their data input. A `DataFrame` is a query derived from the tables in your workspace, built with `ws.table(name)` or `ws.sql(...)`. It is the one input that ML and reasoning accept.

## `op.reasoning.fit()`

```python
op.reasoning.fit(
    df: DataFrame,
    *,
    task: Task | None = None,
    hpo_space: HPOSpace | None = None,
    metric: Metric | list[Metric] | None = None,
    optimizer: Optimizer | None = None,
    random_state: int = 42,
) -> ReasoningFitJob
```

Submits a training job and returns a non-blocking `Job` handle immediately. Call `.wait()` on the handle to block until training completes and receive the trained `ReasoningModel`.

### Parameters

<ParamField body="df" type="DataFrame" required>
  Training data as a `DataFrame`. Build one from a registered table with `ws.table("customers")` or `ws.sql("SELECT ... FROM customers")`, optionally chaining `filter`, `select`, `join`, and other relational ops. The column you name in `task`'s `label_column` is used as the target; all remaining columns are treated as features.
</ParamField>

<ParamField body="task" type="Task | None">
  The supervised learning task, which carries the target `label_column`. Pass the config that matches your problem:

  | Config | Use when |
  | --- | --- |
  | `op.Binclass(label_column=...)` | Binary classification (e.g. churn, fraud, approval) |
  | `op.Multiclass(label_column=...)` | Multi-class classification (three or more discrete classes) |
  | `op.Regression(label_column=...)` | Continuous numerical target |
  | `op.Forecasting(label_column=..., id_column=..., timestamp_column=..., horizon=..., lookback=...)` | Time-series forecasting |
  | `op.SequenceBinclass(label_column=..., id_column=..., timestamp_column=...)` | Per-entity binary classification over each entity's sequence |
  | `op.SequenceMulticlass(label_column=..., id_column=..., timestamp_column=...)` | Per-entity multi-class classification over each entity's sequence |
  | `op.SequenceRegression(label_column=..., id_column=..., timestamp_column=...)` | Per-entity regression over each entity's sequence (accepted, not yet executable) |

  Required for supervised training.
</ParamField>

<ParamField body="hpo_space" type="HPOSpace | None">
  The surrogate search space for the reasoning model, built with `op.HPOSpace.from_dict(...)` or `op.HPOSpace().add(...)` (a raw `dict` is rejected). A reasoning fit searches a single model family, so pass one family. When `None`, OuterProduct picks a surrogate based on your dataset's size and schema. See [The `HPOSpace` class](/sdk/trainer#the-hpospace-class) for the full builder reference.
</ParamField>

<ParamField body="metric" type="Metric | list[Metric] | None">
  The evaluation metric used to score the surrogate. When `None`, OuterProduct picks a sensible default for the task. (Multi-objective optimization over a list of metrics is available on the [`Trainer`](/sdk/trainer) path.)
</ParamField>

<ParamField body="optimizer" type="Optimizer | None">
  How to search the surrogate space: the sampler and a round-structured trial budget, built with `op.Optimizer(kind=..., n_trials_per_step=..., n_steps=...)`. When `None`, the server uses a default optimizer. See [The `Optimizer` class](/sdk/trainer#the-optimizer-class) for details.
</ParamField>

<ParamField body="random_state" default="42" type="int">
  Seed for the training search, for reproducible runs. Defaults to `42`.
</ParamField>

### Return value

<ResponseField name="returns" type="Job[ReasoningModel]">
  A non-blocking job handle. The job runs on OuterProduct's hosted infrastructure. Use the methods below to interact with it.

  <Expandable title="Job methods">
    <ResponseField name=".wait()" type="ReasoningModel">
      Blocks the current thread until the job completes, then returns the trained `ReasoningModel`. This is the most common pattern for scripts and notebooks.
    </ResponseField>

    <ResponseField name=".status()" type="str">
      Returns the current job state without blocking: `"pending"`, `"running"`, `"completed"`, or `"failed"`.
    </ResponseField>

    <ResponseField name=".results()" type="any">
      Returns the raw result payload once the job has completed. Prefer `.wait()` for typed access to the model.
    </ResponseField>
  </Expandable>
</ResponseField>

### Examples

<CodeGroup>

```python Basic training
import outerproduct as op

op.init(api_key="your-api-key")
ws = op.Workspace()

ws.register_csv("customers.csv", table_name="customers")
train = ws.table("customers")

model = op.reasoning.fit(
    train,
    task=op.Binclass(label_column="churn"),
).wait()  # ReasoningModel

# Score new rows by querying the workspace.
recent = ws.table("customers").filter(op.col("signup_year") == 2025)
predictions = model.predict(recent)
reasoning   = model.explain(recent)
```

```python With a custom space and optimizer
model = op.reasoning.fit(
    train,
    task=op.Binclass(label_column="loan_default"),
    hpo_space=op.HPOSpace.from_dict({"models": [{"family": "tabm"}]}),
    optimizer=op.Optimizer(kind="tpe", n_trials_per_step=4, n_steps=5),
).wait()
```

```python Non-blocking with status polling
import time

job = op.reasoning.fit(
    train, task=op.Binclass(label_column="churn")
)

while job.status() in ("pending", "running"):
    print(f"Job status: {job.status()}")
    time.sleep(10)

model = job.wait()
```

</CodeGroup>

<Tip>
  For large datasets or long hyperopt runs, use the non-blocking pattern and poll `job.status()` so your script can do other work while training proceeds.
</Tip>

## `op.reasoning.pattern_tracker.fit()`

```python
op.reasoning.pattern_tracker.fit(
    reasoning_model: ReasoningModel,
    df: DataFrame,
    *,
    target_range: tuple[float | None, float | None],
) -> Job[PatternTracker]
```

Distils a `ReasoningModel`'s explanation behaviour on a specific prediction band into a compact, portable set of named filter patterns. The fitted `PatternTracker` can then be applied to any schema-compatible `DataFrame` to score rows against those patterns.

### Parameters

<ParamField body="reasoning_model" type="ReasoningModel" required>
  A trained `ReasoningModel` (produced by `op.reasoning.fit().wait()`). The tracker learns from this model's explanations over the supplied `df`.
</ParamField>

<ParamField body="df" type="DataFrame" required>
  The `DataFrame` used to fit the tracker. The tracker analyses the model's predictions and attributions over these rows to extract recurring patterns within the `target_range`.
</ParamField>

<ParamField body="target_range" type="tuple[float | None, float | None]" required>
  An inclusive prediction band that defines which rows are considered "positive" examples for pattern extraction. Either bound may be `None` for an open-ended range; at least one bound must be set.

  | `target_range` | Selects |
  | --- | --- |
  | `(0.5, None)` | `pred >= 0.5`, likely-positive cohort |
  | `(None, 0.5)` | `pred <= 0.5`, likely-negative cohort |
  | `(0.4, 0.6)` | `0.4 <= pred <= 0.6`, borderline / uncertain band |
</ParamField>

### Return value

<ResponseField name="returns" type="Job[PatternTracker]">
  A non-blocking job handle. Call `.wait()` to block until fitting completes and receive the `PatternTracker`. You can also poll with `.status()` or access the raw payload with `.results()`.
</ResponseField>

```python
import outerproduct as op

op.init(api_key="your-api-key")
ws = op.Workspace()

ws.register_csv("customers.csv", table_name="customers")
train = ws.table("customers")

model = op.reasoning.fit(
    train, task=op.Binclass(label_column="churn")
).wait()

pt = op.reasoning.pattern_tracker.fit(
    model,
    train,
    target_range=(0.5, None),  # analyse rows where pred >= 0.5
).wait()

print(f"{len(pt.patterns)} patterns; coverage={pt.coverage_fit:.0%}")
```

## PatternTracker

`PatternTracker` is produced by `op.reasoning.pattern_tracker.fit().wait()`. It holds a set of named filter patterns and can score any schema-compatible rows against them. The apply methods (`transform`, `distribution`, `partition`) take raw rows (a pandas DataFrame, NumPy array, or list of rows), not a workspace `DataFrame`.

### Attributes

<ResponseField name="patterns" type="list[FilterPattern]">
  The patterns discovered during fitting. Each entry is a `FilterPattern` with a human-readable label and quality metrics. See [FilterPattern](#filterpattern) below.
</ResponseField>

<ResponseField name="coverage_fit" type="float">
  Fraction of rows in the fitting dataset that are matched by at least one pattern. A value of `0.82` means 82 % of the fitting set falls under at least one named pattern.
</ResponseField>

### Methods

#### `pt.transform()`

```python
pt.transform(X) -> pd.DataFrame
```

Returns a boolean `pandas.DataFrame` of shape `(n_rows, n_patterns)`. Each column corresponds to one pattern (named by `FilterPattern.label`); a cell is `True` if that row matches that pattern. Rows can match multiple patterns simultaneously.

<ParamField body="X" type="pandas.DataFrame | np.ndarray | list" required>
  New rows to score, as a pandas DataFrame, NumPy array, or list of rows. Must be schema-compatible with the data used to fit the tracker.
</ParamField>

<ResponseField name="returns" type="pd.DataFrame">
  Boolean DataFrame of shape `(n_rows, n_patterns)`. Column names match the `FilterPattern.label` values in `pt.patterns`.
</ResponseField>

#### `pt.distribution()`

```python
pt.distribution(X) -> pd.Series
```

Returns match rates (the fraction of rows in `X` that match each pattern) as a `pd.Series` indexed by pattern label.

<ParamField body="X" type="pandas.DataFrame | np.ndarray | list" required>
  New rows to score, as a pandas DataFrame, NumPy array, or list of rows.
</ParamField>

<ResponseField name="returns" type="pd.Series">
  Float Series of shape `(n_patterns,)`, indexed by `FilterPattern.label`. Values are in `[0, 1]`.
</ResponseField>

#### `pt.partition()`

```python
pt.partition(X) -> dict[str, np.ndarray]
```

Returns a dict mapping each pattern label to the integer row indices in `X` that match it. Useful when you want to extract the actual rows belonging to each pattern segment.

<ParamField body="X" type="pandas.DataFrame | np.ndarray | list" required>
  New rows to score, as a pandas DataFrame, NumPy array, or list of rows.
</ParamField>

<ResponseField name="returns" type="dict[str, np.ndarray]">
  Mapping from pattern label to a 1-D integer array of matching row indices. A row may appear under multiple pattern labels.
</ResponseField>

### Full usage example

```python
import outerproduct as op

op.init(api_key="your-api-key")
ws = op.Workspace()

# --- Fit ---
ws.register_csv("customers.csv", table_name="customers")
train = ws.table("customers")

model = op.reasoning.fit(
    train, task=op.Binclass(label_column="churn")
).wait()

pt = op.reasoning.pattern_tracker.fit(
    model,
    train,
    target_range=(0.5, None),
).wait()

# Inspect the discovered patterns
print(f"{len(pt.patterns)} patterns; coverage={pt.coverage_fit:.0%}")
for fp in pt.patterns:
    print(f"  {fp.label}: precision={fp.precision:.2f}, lift={fp.lift:.2f}")

# --- Apply to new data (the apply methods take raw rows) ---
import pandas as pd

X_new = pd.read_csv("new_customers.csv")

# Boolean match matrix
match_matrix = pt.transform(X_new)
print(match_matrix.head())

# Match rates per pattern
print(pt.distribution(X_new))

# Row indices per pattern
segments = pt.partition(X_new)
for label, indices in segments.items():
    print(f"{label}: {len(indices)} matching rows")
```

<Warning>
  `transform()`, `distribution()`, and `partition()` require `X` to be schema-compatible with the data used to fit the tracker. Mismatched column names raise a validation error before scoring.
</Warning>

## FilterPattern

A single named pattern discovered by the `PatternTracker`.

<ResponseField name="label" type="str">
  A human-readable name for the pattern, generated by OuterProduct to summarise the feature conditions that define it (e.g. `"high_credit_low_income"`).
</ResponseField>

<ResponseField name="precision" type="float">
  Fraction of rows matching this pattern whose prediction also falls within `target_range`. Higher precision means the pattern is a more reliable indicator of the target cohort. Values are in `[0, 1]`.
</ResponseField>

<ResponseField name="lift" type="float">
  Ratio of the pattern's precision to the base rate of `target_range` in the fitting dataset. A lift of `2.0` means rows matching this pattern are twice as likely to fall in the target band as a randomly chosen row.
</ResponseField>

```python
for fp in pt.patterns:
    print(f"{fp.label}")
    print(f"  precision : {fp.precision:.2%}")
    print(f"  lift      : {fp.lift:.2f}x")
# high_credit_low_income
#   precision : 91.30%
#   lift      : 2.41x
# recent_late_payments
#   precision : 87.50%
#   lift      : 2.31x
```
