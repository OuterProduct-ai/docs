A `Workspace` registers tables from external sources with three methods: `ws.register_s3`, `ws.register_snowflake`, and `ws.register_databricks`. Each registers a source table that lives in the cloud system, with no intermediate download or local processing, and returns the table's `DataFrame`. You then query it with `ws.table(name)` or `ws.sql(...)`. For local files and in-memory frames, see the [Workspace reference](/sdk/dataset).

All three share the same shape:

```python
ws.register_<source>(table_name, source_locator, connector="<console-credential-name>")
```

<Note>
  For all external connectors (S3, Snowflake, and Databricks), your cloud credentials are **never** passed through the SDK. You store them once in the [OuterProduct Console](https://console.outerproduct.com) under **Connectors**, and the SDK references them by the name you assigned with the `connector` argument. The OuterProduct backend uses those stored credentials at training and inference time.
</Note>

---

## register_s3

`ws.register_s3` registers a parquet file stored in Amazon S3. You supply the name of a pre-configured S3 credential from the OuterProduct Console, and the backend reads your data at training time using a cross-account IAM role, so no AWS access keys are required in your code.

<Steps>
  <Step title="Add an S3 credential in the Console">
    Log in to [console.outerproduct.com](https://console.outerproduct.com), navigate to **Connectors**, and click **New Connector**. Select **S3**, enter your bucket details, and follow the wizard to attach the OuterProduct trust policy to a role in your AWS account.
  </Step>
  <Step title="Use the credential name in the SDK">
    Pass the name you gave the connector to `register_s3(..., connector=...)`. The backend resolves the stored credentials automatically.
  </Step>
</Steps>

```python
import outerproduct as op

op.init()
ws = op.Workspace()

ws.register_s3("customers", "s3://my-bucket/data/customers.parquet", connector="prod-aws")

train = ws.table("customers")
model = op.reasoning.fit(train, task=op.Binclass(label_column="churn")).wait()
```

### Signature

```python
ws.register_s3(table_name, url, connector)
```

<ParamField path="table_name" type="str" required>
  Name to register the table under in the workspace. Query it later with `ws.table(table_name)`.
</ParamField>

<ParamField path="url" type="str" required>
  The fully-qualified S3 URL of the parquet file (e.g. `"s3://my-bucket/data/customers.parquet"`). Must start with `s3://`.
</ParamField>

<ParamField path="connector" type="str" required>
  The name of the S3 credential stored in the OuterProduct Console. This name maps to the IAM role that OuterProduct uses to access your bucket.
</ParamField>

<ResponseField name="DataFrame" type="DataFrame">
  The `DataFrame` for the newly registered table. The data is read by the OuterProduct backend at training time.
</ResponseField>

## register_snowflake

`ws.register_snowflake` registers a table stored in Snowflake. The backend reads the table using a Programmatic Access Token (PAT) that you registered in the Console, so no PAT appears in your SDK code.

<Steps>
  <Step title="Add a Snowflake credential in the Console">
    Log in to [console.outerproduct.com](https://console.outerproduct.com), navigate to **Connectors**, and click **New Connector**. Select **Snowflake** and paste your account details and a Programmatic Access Token. To generate a PAT, open Snowsight and go to **Governance & Security → Users & roles**, select your user, and choose **Programmatic access tokens → Generate new token**.
  </Step>
  <Step title="Use the credential name in the SDK">
    Pass the connector name to `register_snowflake(..., connector=...)`. The backend resolves the stored PAT automatically.
  </Step>
</Steps>

```python
import outerproduct as op

op.init()
ws = op.Workspace()

ws.register_snowflake("customers", "MYDB.PUBLIC.CUSTOMERS", connector="prod-snowflake")

train = ws.table("customers")
model = op.reasoning.fit(train, task=op.Binclass(label_column="churn")).wait()
```

### Signature

```python
ws.register_snowflake(table_name, source_locator, connector)
```

<ParamField path="table_name" type="str" required>
  Name to register the table under in the workspace. Query it later with `ws.table(table_name)`.
</ParamField>

<ParamField path="source_locator" type="str" required>
  The fully-qualified Snowflake table in `DATABASE.SCHEMA.TABLE` form (e.g. `"MYDB.PUBLIC.CUSTOMERS"`).
</ParamField>

<ParamField path="connector" type="str" required>
  The name of the Snowflake credential stored in the OuterProduct Console. The backend uses this credential to authenticate against Snowflake at training time.
</ParamField>

<ResponseField name="DataFrame" type="DataFrame">
  The `DataFrame` for the newly registered table. The data is read by the OuterProduct backend at training time.
</ResponseField>

## register_databricks

`ws.register_databricks` registers a table in a Databricks SQL warehouse or cluster. The backend reads the table using a personal access token that you registered in the Console, so no token is passed through the SDK.

<Steps>
  <Step title="Add a Databricks credential in the Console">
    Log in to [console.outerproduct.com](https://console.outerproduct.com), navigate to **Connectors**, and click **New Connector**. Select **Databricks** and paste your workspace credentials. To create a personal access token, open your Databricks account, go to **Settings → Developer → Access tokens**, and click **Generate new token**, choosing **Other APIs** as the token type.
  </Step>
  <Step title="Use the credential name in the SDK">
    Pass the connector name to `register_databricks(..., connector=...)`. The backend resolves the stored token automatically.
  </Step>
</Steps>

```python
import outerproduct as op

op.init()
ws = op.Workspace()

ws.register_databricks("customers", "main.default.customers", connector="prod-databricks")

train = ws.table("customers")
model = op.reasoning.fit(train, task=op.Binclass(label_column="churn")).wait()
```

### Signature

```python
ws.register_databricks(table_name, source_locator, connector)
```

<ParamField path="table_name" type="str" required>
  Name to register the table under in the workspace. Query it later with `ws.table(table_name)`.
</ParamField>

<ParamField path="source_locator" type="str" required>
  The fully-qualified Databricks table in `catalog.schema.table` form (e.g. `"main.default.customers"`).
</ParamField>

<ParamField path="connector" type="str" required>
  The name of the Databricks credential stored in the OuterProduct Console. The backend uses this personal access token to authenticate against Databricks at training time.
</ParamField>

<ResponseField name="DataFrame" type="DataFrame">
  The `DataFrame` for the newly registered table. The data is read by the OuterProduct backend at training time.
</ResponseField>

## Query across your sources

A workspace can hold tables from more than one system at once, and `ws.sql(...)` joins across them. Register an S3 dataset, a Snowflake table, and a Databricks table, then build one training set from all three:

```python
ws.register_s3("events", "s3://acme-data/events.parquet", connector="prod-aws")
ws.register_snowflake("customers", "ANALYTICS.PUBLIC.CUSTOMERS", connector="prod-snowflake")
ws.register_databricks("payments", "main.finance.payments", connector="prod-databricks")

train = ws.sql("""
    SELECT
        c.customer_id,
        c.signup_year,
        c.plan,
        COUNT(e.event_id) AS events_30d,
        SUM(p.amount)     AS revenue_90d,
        c.churned
    FROM customers c
    LEFT JOIN events e   ON e.customer_id = c.customer_id
    LEFT JOIN payments p ON p.customer_id = c.customer_id
    GROUP BY c.customer_id, c.signup_year, c.plan, c.churned
""")

model = op.reasoning.fit(train, task=op.Binclass(label_column="churned")).wait()
```

The join runs server-side, and the credentials for each source stay in the Console.
