Connectors let OuterProduct read tables from S3, Snowflake, and Databricks.

Create the connector in the [OuterProduct Console](https://console.outerproduct.com) first. Then pass the connector name when you register a table in the SDK.

All connector methods use the same shape:

```python
ws.register_<source>(table_name, source_locator, connector="<console-connector-name>")
```

<Note>
  Your cloud credentials are not passed through the SDK. S3 uses an IAM role. Snowflake and Databricks use workload identity federation with short-lived OAuth tokens.
</Note>

---

## register\_s3

`ws.register_s3` registers a parquet file stored in Amazon S3. OuterProduct reads it by assuming the IAM role configured in the Console.

<Steps>
  <Step title="Add an S3 connector in the Console">
    Select **S3** and enter your S3 URI. In AWS, create an IAM role with the generated custom trust policy, attach the generated S3 permissions policy to the same role, and paste the role ARN back into the wizard.
  </Step>
  <Step title="Use the connector name in the SDK">
    Pass the connector name to `register_s3(..., connector=...)`.
  </Step>
</Steps>

```python
import outerproduct as op

op.init()
ws = op.Workspace()

ws.register_s3("customers", "s3://my-bucket/data/customers.parquet", connector="prod-aws")

train = ws.table("customers")
model = op.reasoning.fit(train, task=op.Binclass(label_column="churn")).wait()
```

### Signature

```python
ws.register_s3(table_name, url, connector)
```

<ParamField path="table_name" type="str" required>
  Name to register the table under. Query it later with `ws.table(table_name)`.
</ParamField>

<ParamField path="url" type="str" required>
  The S3 URL of the parquet file, for example `"s3://my-bucket/data/customers.parquet"`.
</ParamField>

<ParamField path="connector" type="str" required>
  The name of the S3 connector stored in the Console. OuterProduct assumes the IAM role saved in that connector.
</ParamField>

<ResponseField name="DataFrame" type="DataFrame">
  The `DataFrame` for the registered table.
</ResponseField>

## register\_snowflake

`ws.register_snowflake` registers a table stored in Snowflake. OuterProduct authenticates with Snowflake workload identity federation, an OAuth-token-based authentication flow.

<Steps>
  <Step title="Add a Snowflake connector in the Console">
    Select **Snowflake**, enter your Snowflake account identifier, and run the generated setup SQL in Snowflake.
  </Step>
  <Step title="Use the connector name in the SDK">
    Pass the connector name to `register_snowflake(..., connector=...)`.
  </Step>
</Steps>

```python
import outerproduct as op

op.init()
ws = op.Workspace()

ws.register_snowflake("customers", "MYDB.PUBLIC.CUSTOMERS", connector="prod-snowflake")

train = ws.table("customers")
model = op.reasoning.fit(train, task=op.Binclass(label_column="churn")).wait()
```

### Signature

```python
ws.register_snowflake(table_name, source_locator, connector)
```

<ParamField path="table_name" type="str" required>
  Name to register the table under. Query it later with `ws.table(table_name)`.
</ParamField>

<ParamField path="source_locator" type="str" required>
  The Snowflake table in `DATABASE.SCHEMA.TABLE` form, for example `"MYDB.PUBLIC.CUSTOMERS"`.
</ParamField>

<ParamField path="connector" type="str" required>
  The name of the Snowflake connector stored in the Console.
</ParamField>

<ResponseField name="DataFrame" type="DataFrame">
  The `DataFrame` for the registered table.
</ResponseField>

## register\_databricks

`ws.register_databricks` registers a table in Databricks. OuterProduct authenticates with Databricks OAuth token federation. OuterProduct gets an AWS IAM OIDC token through STS, then Databricks exchanges it for a Databricks OAuth token using OAuth 2.0 Token Exchange (RFC 8693).

<Steps>
  <Step title="Add a Databricks connector in the Console">
    Select **Databricks** and enter your workspace URL, SQL warehouse HTTP path, and service principal. Run the generated Databricks account-level federation policy command, then grant that service principal access to the warehouse and tables.
  </Step>
  <Step title="Use the connector name in the SDK">
    Pass the connector name to `register_databricks(..., connector=...)`.
  </Step>
</Steps>

```python
import outerproduct as op

op.init()
ws = op.Workspace()

ws.register_databricks("customers", "main.default.customers", connector="prod-databricks")

train = ws.table("customers")
model = op.reasoning.fit(train, task=op.Binclass(label_column="churn")).wait()
```

### Signature

```python
ws.register_databricks(table_name, source_locator, connector)
```

<ParamField path="table_name" type="str" required>
  Name to register the table under. Query it later with `ws.table(table_name)`.
</ParamField>

<ParamField path="source_locator" type="str" required>
  The Databricks table in `catalog.schema.table` form, for example `"main.default.customers"`.
</ParamField>

<ParamField path="connector" type="str" required>
  The name of the Databricks connector stored in the Console.
</ParamField>

<ResponseField name="DataFrame" type="DataFrame">
  The `DataFrame` for the registered table.
</ResponseField>

## Query across your sources

A workspace can hold tables from more than one system. `ws.sql(...)` can join them.

```python
ws.register_s3("events", "s3://acme-data/events.parquet", connector="prod-aws")
ws.register_snowflake("customers", "ANALYTICS.PUBLIC.CUSTOMERS", connector="prod-snowflake")
ws.register_databricks("payments", "main.finance.payments", connector="prod-databricks")

train = ws.sql("""
    SELECT
        c.customer_id,
        c.signup_year,
        c.plan,
        COUNT(e.event_id) AS events_30d,
        SUM(p.amount)     AS revenue_90d,
        c.churned
    FROM customers c
    LEFT JOIN events e   ON e.customer_id = c.customer_id
    LEFT JOIN payments p ON p.customer_id = c.customer_id
    GROUP BY c.customer_id, c.signup_year, c.plan, c.churned
""")

model = op.reasoning.fit(train, task=op.Binclass(label_column="churned")).wait()
```

The join runs server-side, and the connector configuration for each source stays in the Console.
