## Model

### Methods

- `predict(df)` — run inference on held-out data. Returns a NumPy array of shape `(n_rows, n_outputs)`: class probabilities for classification, predicted values for regression. Inputs are capped at 100k rows per call.
- `rename(name)` — set or change the model's name (unique within your org). Raises if the name is already taken.

### Properties

All read-only.

| Property | Type | Description |  |
| :-- | :-- | :-- | --- |
| `id` | `str` | Server-assigned model UUID. |  |
| `short_id` | \`str | None\` | Short, human-friendly handle (e.g. `mdl-7bQ2xV9mKp4R`) — the value shown in the UI. |
| `name` | \`str | None\` | Model name, if one has been assigned. |
| `hyperparameters` | \`dict | None\` | The winning trial's hyperparameters (specific to the model family). |
| `validation_metrics` | \`dict\[str, float\] | None\` | Cross-validation scores, keyed by metric name. |
| `feature_names` | \`list\[str\] | None\` | Names of the input features. |
| `schema` | `list[FieldDef]` | Input feature schema — each field's name and datatype. |  |
| `label_column` | \`str | None\` | Name of the target column. |

### Model curve

When you optimize more than one metric, `.wait()` returns a `ModelCurve` instead of a single model: the **Pareto frontier** of models, one per non-dominated trade-off between your metrics.

```python
for model, metrics in curve:
    print(model.short_id, metrics["auc"])
```

Each entry pairs a trained `model` with a `metrics` dict mapping every requested metric name to that model's value. The curve is also indexable and sized  (`curve[0]`, `len(curve)`) and exposes

- `.models` — the list of models alone
- `.metrics` — the list of metric dicts alone

Every model on the curve exposes the same methods and properties above.

### Loading a trained model

Models persist after training, so you don't need to refit to reuse one. If you have a handle to a model from a previous run, fetch it with `op.get_model()`:

```python
model = op.get_model("mdl-7bQ2xV")   # short_id, UUID, or name
proba = model.predict(test_features)
```

The argument can be **any handle the model has**, and the kind is inferred from its shape:

- a **UUID** — the opaque `id`
- a value starting with `mdl-` — the `short_id` shown in the UI
- **anything else** — the model's org-unique **name** (e.g. `op.get_model("q3-churn")`)

The returned object is fully functional and identical to one straight from a fit: the same `predict()`, the same properties, and the correct type for the task (tabular or sequence). Its metadata is preloaded, so reading `.hyperparameters` or `.validation_metrics` right after the call doesn't cost an extra request.

### Listing your models

To see every model in your org, use `op.get_models()`:

```python
for model in op.get_models():
    print(model.short_id, model.name, model.validation_metrics)
```

It returns a `list` of the same model objects `op.get_model()` gives you — so you can filter or sort in plain Python (for example, by a validation metric) and call `predict()` on any of them directly:

```python
models = op.get_models()
best = max(models, key=lambda m: m.validation_metrics["auc"])
proba = best.predict(test_features)
```
