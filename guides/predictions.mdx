Once you have a trained model, generating predictions is a single method call. Both `Model` and `ReasoningModel` expose a `predict()` method that accepts a `DataFrame`, validates it against the training-time schema, and returns a `numpy.ndarray`. If you're working with a `ReasoningModel` and need both predictions and explanations, you can get both in a single round-trip.

## Build a DataFrame of inference rows

`predict()` takes a `DataFrame`: a query over the tables in your workspace. Build one that selects the rows you want to score with `ws.table(...)` or `ws.sql(...)`, then pass it to the model.

```python
import outerproduct as op

op.init()
ws = op.Workspace()

# Select the rows to score. The model ignores the label column at inference time.
score = ws.table("customers").filter(op.col("signup_year") == 2025)
predictions = model.predict(score)  # numpy.ndarray
```

<Note>
  The SDK validates the query's columns against the model's training-time schema **before** the call goes out. Missing or mismatched features raise a clear local error rather than a server-side 400, so you catch schema mismatches fast.
</Note>

You build the inference `DataFrame` the same way you built the training set: chain relational ops off a table, or write SQL.

```python
# Filter an existing table to the rows you want to score.
score = ws.table("customers").filter(op.col("region") == "EU")

# Or register new rows that arrived as a file, then query them.
ws.register_csv("new_customers.csv", table_name="new_customers")
score = ws.table("new_customers")

# Or write SQL.
score = ws.sql("SELECT * FROM customers WHERE signup_year = 2025")
```

## Predict and explain in one call

If you have a `ReasoningModel`, use `predict_and_explain()` to avoid two separate round-trips. You get both the prediction array and a `Reasoning` object with per-sample feature attributions.

```python
score = ws.table("customers").filter(op.col("signup_year") == 2025)
predictions, reasoning = model.predict_and_explain(score)
```

<Tip>
  Prefer `predict_and_explain()` over calling `predict()` and `explain()` separately. It halves your network overhead and guarantees the predictions and attributions correspond to exactly the same forward pass.
</Tip>

## What predict() returns

`predict()` returns a `numpy.ndarray`. For binary classification, values are class probabilities. For regression, values are the predicted targets.

```python
score = ws.table("customers").filter(op.col("signup_year") == 2025)
predictions = model.predict(score)

print(type(predictions))        # <class 'numpy.ndarray'>
print(predictions.shape)        # (n_samples,)
print(predictions[:5])          # e.g. [0.82, 0.14, 0.91, 0.37, 0.66]
```
