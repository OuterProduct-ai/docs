## Introduction

Customer data is typically high dimensional and noisy, making it difficult for sales and marketing teams to identify their best customers. The key problem that growth teams are solving for is "how do we know which customers are likely to convert? and why?" Using [publicly available dataset from Kaggle](https://www.kaggle.com/datasets/amritachatterjee09/lead-scoring-dataset/data), we'll demonstrate how our SDK can help you build highly performant lead scoring models that are natively explainable.

</Info>

## Workflow overview

Here's the overarching workflow we will be following:

1. **Authentication:** Installing and setting up the SDK with the appropriate credentials 
2. **Upload data:** Register dataset on OuterProduct
3. **Data transformation:** Transform the data so that it's ready for modeling
4. **Modeling and evaluation:** Build and optimize the model; evaluate its performance
5. **Reasoning:** Surface reasoning and context for each prediction

## Upload data

#### Data overview

For this project we'll be using the lead scoring dataset that is publicly available on Kaggle. The dataset contains ~9000 historical leads, along with \>30 features characterizing each customer. Furthermore, there is a good amount of missing entries for some of the features, key characteristic that's reflected in most enterprise data. We will show how the SDK can effectively handle such problem.

#### Data registration

After downloading the data from Kaggle, we can register it in OuterProduct as such:

```python
# Data registering
ws.register_csv(
    'data/lead_scoring.csv', 
    table_name=dataset_name
)
```

#### Data transformation

Here are a few things that we will do to prep the data for modeling:

1. Add an index column since existing `Prospect ID` and `Lead Number` fields are noisy and difficult to work with
2. Drop the `Prospect ID` and `Lead Number` fields
3. Divide the data into training / test split following 80 / 20 split

Notably, the SDK already handles missing fields for you during a training job:

- Missing string values are replaced with "\_\_missing\_\_" and 
- Missing int / float values are replaced with the median value of existing values for that feature

```python
# Data cleaning
# adding index column
INDEX_COL = "_idx"
# Assign 0 .. n-1 using Lead Number only for ordering (not kept as a feature)
indexed = ws.sql(f"""
    SELECT
        *,
        CAST(ROW_NUMBER() OVER (ORDER BY "Lead Number") AS BIGINT) - 1 AS {INDEX_COL}
    FROM lead_scoring
""")

#Drop features
processed_table = indexed.drop("Prospect ID", "Lead Number")

# Split by INDEX_COL into train and test data
n = processed_table.count()
split = int(0.8 * n)
train_tbl = processed_table.filter(op.col(INDEX_COL) < split).sort_by(INDEX_COL)
test_tbl = processed_table.filter(op.col(INDEX_COL) >= split).sort_by(INDEX_COL)
```

## Modeling

To create a reasoning model, we need to define three objects:

1. [Task](/guides/models/task)
2. [Hyper-parameter optimization space](/guides/models/hpospace)
3. [Optimizer](/guides/models/optimizer)

#### Task

Here we define the training task for the model. In our case, we want a binary classification task predicting the "converted" feature.

```python
# Define task
task = op.Binclass(label_column = "converted")
```

#### HPO Space

The HPO space specifies the model families and the hyper-parameters that we want to search through to find the best one for our model.

```python
# Define HPO Space
# xRFM: recursive feature machine (https://arxiv.org/abs/2508.10053)
xrfm = (
    op.ModelParamSpace(family="xrfm")
    .float("bandwidth", 1.0, 20.0, log=True)
    .float("exponent", 0.5, 2.0)
    .int("iters", 4, 6)
)

# TabM: MLP-style tabular net (https://arxiv.org/abs/2410.24210)
tabm = (
    op.ModelParamSpace(family="tabm")
    .float("lr", 1e-4, 3e-3, log=True)
    .categorical("n_blocks", [1, 2, 3, 4])
    .int("d_block", 64, 512, log=True)
)

hpo_space = op.HPOSpace().add(tabm).add(xrfm)
```

#### Optimizer

Lastly, the optimizer object specifies the number of steps and trials to take during the search, as well as the search method itself:

```python
# Define optimizer
optimizer = op.Optimizer(
    kind="tpe", 
    n_trials_per_step=4, 
    n_steps=5
)
```

#### Training

With our object definitions in place, we can submit a training job for our reasoning model.

<Info>
  Note that op.reasoning.fit() creates a `ReasoningFitJob` object, which is not the model itself
</Info>

```python
# Training Model
job = op.reasoning.fit(
    train_tbl.drop(INDEX_COL),  # all features except index as it is non-predictive
    task=task,
    hpo_space=hpo_space,
    optimizer=optimizer,
)
model = job.wait() # Wait until job is finished and return the model
```

#### Evaluation

We can then check model accuracy to see how well it performs against the test data:

```python
# Performance Evaluation
import numpy as np
import pandas as pd
from sklearn.metrics import accuracy_score

label = "converted"

def evaluate(model, frame, split_id, label):
    label_tbl = frame.select(split_id, label).materialize()
    actual = label_tbl.column(label).to_numpy().astype(int)
    feat_df = frame.drop(label)

    proba = np.asarray(model.predict(feat_df.drop(split_id)))
    if proba.ndim == 2 and proba.shape[1] > 1:
        pred_class = proba.argmax(axis=1)
    else:
        pred_class = (proba.ravel() >= 0.5).astype(int)
    return accuracy_score(actual, pred_class)

print("training accuracy: ", evaluate(model, train_tbl, INDEX_COL, label))
print("test accuracy: ", evaluate(model, test_tbl, INDEX_COL, label))
```
