## What OuterProduct does

OuterProduct lets you define the universe of your data through a `Workspace`, then combines the ergonomics of a data querying system with our reasoning engine. You shape the data the way you already think about it (filter, join, derive columns), and train models that return predictions together with the reasoning behind each one.

It is a full ML platform. You get model search across a portfolio of architectures, multi-metric optimization, and hyperparameter tuning. On top of that sits the reasoning layer: feature-level explanations for every prediction, population-level patterns, and counterfactuals that show what would flip an outcome.

The query engine embedded in the workspace is based on [Apache DataFusion](https://datafusion.apache.org/), so your queries run as real relational plans against your source tables wherever they live: S3, Snowflake, Databricks, or data you upload.

## The dataset is a query

The table you train on is rarely a raw table. It is a filter, a join, and a few derived columns away from what your warehouse stores, and it changes as new data lands. So OuterProduct treats the dataset as a query, not a copied file.

You point a `Workspace` at your source tables, narrow to the population you care about, and pass that query to `fit`. Nothing runs locally and there is no copy to keep in sync; the query executes server-side against your data. Re-run the script and it re-executes against current rows. Because you score with the same query you trained on, the training set and the inference set are built the same way.

## A short example

```python
import outerproduct as op

op.init()  # reads OUTERPRODUCT_API_KEY from the environment

ws = op.Workspace()

# Register a source table once. S3 here; Snowflake and Databricks work the same way.
ws.register_s3("customers", "s3://acme-data/customers.parquet", connector="prod-aws")

# Build the training set as a query over that source.
train = ws.table("customers").filter(op.col("signup_year") >= 2020)

# Train a model that predicts and explains.
model = op.reasoning.fit(train, task=op.Binclass(label_column="churn")).wait()

# Score this year's customers; get predictions and feature-level reasoning.
recent = ws.table("customers").filter(op.col("signup_year") == 2025)
predictions = model.predict(recent)
reasoning = model.explain(recent)

print(reasoning.feature_names)
print(reasoning.attributions.shape)  # (n_samples, n_features)
```

You can also upload local data when it does not live in a warehouse. `ws.register_csv(...)`, `ws.from_pandas(df)`, and `ws.read_parquet(...)` upload the bytes and register a source table you query the same way.

## Building blocks

OuterProduct is a handful of composable pieces:

- **Workspace**: defines the universe of your data and is the single data entry point. Registers source tables (S3, Snowflake, Databricks, or local uploads) and builds queries over them with `ws.table(name)`.
- **ReasoningModel**: trains a model that returns predictions and feature-level reasoning for each one. Produced by `op.reasoning.fit()`.
- **Trainer**: trains a model optimized across one or more metrics, without the reasoning layer.
- **PatternTracker**: aggregates per-row reasoning across a population into a small set of named, executable patterns.
- **Counterfactuals**: generate minimal, realistic changes that would flip a prediction.
- **MCP server**: use OuterProduct from Claude, Cursor, and other Model Context Protocol clients without writing Python.

## How jobs run

Training and pattern fitting run on OuterProduct's hosted infrastructure, so `fit()` returns a job handle right away. Call `.wait()` to block until the model is ready, or poll `job.status()` and fold the job into your own orchestration.
